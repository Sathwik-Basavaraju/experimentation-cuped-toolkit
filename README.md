# Experimentation Toolkit with Variance Reduction (CUPED) and Sequential Testing

Python, NumPy, SciPy — simulated experiment data (synthetic, generated by the code in this repo).

## What this is

A reusable toolkit for two common experiment-analysis problems:

1. **CUPED variance reduction** — use pre-experiment behaviour to
   reduce the variance of a treatment-effect estimate, so fewer users
   are needed for the same power.
2. **Sequential testing** — peek at results at interim looks without
   inflating the false-positive rate, using O'Brien-Fleming
   boundaries, plus a launch rule with two guardrail metrics.

## Results — actually computed by the simulations in this repo

All numbers below come from `outputs/cuped_metrics.json` and
`outputs/aa_metrics.json`, produced by running the scripts. They are
**not** copied from any external project description.

### CUPED power simulation

- Design: baseline mean 50, baseline SD 10, pre/post correlation
  target 0.55 (observed pooled correlation 0.5482), 3% relative lift
  (delta = 1.5), two-sided alpha 0.05, target power 0.80, 2,000
  experiments per condition, seed 42.
- Theoretical sample size per arm **without CUPED: 698 users**.
- Theoretical sample size per arm **with CUPED: 487 users**.
- **Sample-size reduction: 30.23%** (698 → 487).
- Empirical power at 487 users/arm: naive **65.9%**, CUPED **80.45%**.
- Empirical power at 698 users/arm: naive **80.25%**, CUPED **92.25%**.
- Reading: CUPED reaches the 80% target at the smaller sample size;
  the naive method needs the larger size to reach it.

### A/A peeking simulation

- Design: 10,000 A/A tests (true effect zero), 5 equally spaced
  interim looks, final sample 1,000 users per arm, seed 123.
  Guardrails: two independent null metrics; a launch is blocked if
  either guardrail shows significant harm (z < -1.96) at the look
  where the primary first crosses.
- OBF boundaries used: [4.56, 3.23, 2.64, 2.33, 2.04].
- False-positive rate, naive peeking (|z| > 1.96 at any look): **14.08%**.
- False-positive rate, O'Brien-Fleming: **4.75%**.
- False-launch rate with guardrails, naive: **13.35%**
  (1,335 wrong launches per 10,000 tests).
- False-launch rate with guardrails, OBF: **4.50%**
  (450 wrong launches per 10,000 tests).
- **885 fewer wrong launches per 10,000 tests with OBF** than with
  naive peeking, under this simulation's guardrail definition.
- Note on guardrails: because the guardrails here are null metrics,
  they rarely block a launch (only when they happen to show harm at
  the crossing look), so the false-launch rate is close to the
  false-positive rate. A different guardrail definition (e.g. real
  harm metrics, or checking at the final look only) would give a
  different false-launch rate — the definition used here is stated
  in `src/experimentation/sequential.py` and `scripts/simulate_aa.py`.

## How to run

```bash
pip install -r requirements.txt
python3 scripts/simulate_cuped.py   # writes outputs/cuped_metrics.json
python3 scripts/simulate_aa.py      # writes outputs/aa_metrics.json
python3 scripts/make_charts.py      # writes outputs/charts/*.png
python3 -m pytest tests/ -q         # 4 tests
```

## Files

- `src/experimentation/cuped.py` — CUPED theta, adjustment, variance
  reduction, sample-size calculation.
- `src/experimentation/sequential.py` — OBF boundaries and launch rule.
- `scripts/simulate_cuped.py` — 2,000-experiment CUPED power simulation.
- `scripts/simulate_aa.py` — 10,000-test A/A peeking simulation.
- `scripts/make_charts.py` — power and FPR comparison charts.
- `tests/test_toolkit.py` — unit tests for CUPED, sample size, OBF
  boundaries, and the launch rule.
- `outputs/cuped_metrics.json`, `outputs/aa_metrics.json` — computed results.
- `outputs/charts/power_comparison.png`, `outputs/charts/fpr_comparison.png`.

## Limitations

- All data is simulated normal data with the parameters above;
  real experiment data will have different variance, correlation,
  and guardrail behaviour.
- OBF boundaries are the standard 5-look values for alpha 0.05;
  other look counts use an approximation in `sequential.py` and
  are not validated by the simulation here.
